# 오답노트

## 기록 규칙

**멘탈 모델 오류만 적는다.** 오타, API 이름 착각, 단순 실수는 적지 않는다. 여기에 잡동사니가 쌓이면 다시 읽지 않게 된다.

**`[전제]` 필드를 비워두지 않는다.** 틀린 답이 아니라 **틀린 전제**를 고쳐야 재발하지 않는다. 이 줄을 쓰기 어렵다면 아직 왜 틀렸는지 모르는 것이고, 그건 그 자체로 중요한 신호다.

## 태그

| 태그 | 범위 |
|---|---|
| `#rsc경계` | 서버/클라이언트 구분, `'use client'`, 직렬화, 컴포지션 |
| `#프리렌더` | 정적 셸, PPR, Suspense 경계, `connection()` |
| `#캐싱` | `use cache`, `cacheLife`, 무효화 3종 |
| `#서버실행` | Route Handlers, Server Actions, 쿠키/헤더, proxy |
| `#라우팅` | 파일 규약, 중첩, 동적 세그먼트, 네비게이션 |
| `#언러닝` | Pages Router 습관의 잔재 → `unlearning.md`로 옮긴다 |

## 주기적으로 할 것

- **주 1회** — 이번 주 항목을 다시 읽고 설명 산출물 주제를 고른다
- **단계 종료 시** — 태그별로 집계한다. 한 태그에 몰려 있으면 그 영역을 다시 본다
- **`#언러닝` 항목** — `unlearning.md`로 옮기고 여기서는 지운다

### 19일차 (9/7 · S30·S31 웜업 퀴즈 — 형태를 바꿔 출제)

### 13일차 (9/2 · S26 proxy.ts)
[상황]  proxy 가 "페이지 렌더링 후"에 실행되고, 따라서 쿠키를 "쓸 수 없다"고 예측.

[실제]  렌더링 전에 실행된다 (요청을 가로채는 것이므로). 그래서 쿠키를 쓸 수 있고,
        set-cookie 헤더가 실제로 발급됐다. 정적 파일 포함 모든 요청에 실행된다
[전제]  처음 직관은 "proxy 니까 렌더링 전"으로 맞았는데,
        "렌더링 후에 서버 동작이 실행된다"는 잘못된 전제로 추론해서 뒤집었다.
        렌더링 자체가 서버 동작의 일부인데 순서를 반대로 잡았다.
        직관이 맞는데 논리로 덮어쓰는 경우도 있다
[태그]  #서버실행

주: Q2(쿠키 쓰기)는 Q1(실행 시점)이 틀린 결과다. S25 에서 세운 기준

    기준은 맞고 입력이 틀린 경우.

### 12일차 (9/1 · S25 cookies / headers)
[상황]  서버 컴포넌트에서 쿠키를 못 쓰는 이유를 "서버에 set 권한이 없다"로 예측.
        쓰려면 "클라이언트 컴포넌트에서 해야 한다"고 답
[실제]  권한이 아니라 타이밍 문제. 헤더는 body 보다 먼저 전송되는데
        서버 컴포넌트는 body 를 만드는 중이라 되돌아가 헤더를 끼워넣을 수 없다.
        쓰는 곳은 Server Action 또는 Route Handler — 응답이 시작되기 전이다.
        에러 메시지가 직접 알려준다: "can only be modified in a Server Action or Route Handler"
