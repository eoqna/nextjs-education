# HTTP body는 왜 스트림인가?

**주차:** 1주차
**출처 오답:** 5, 6, 7 일차 항목에서 발생

## 흔한 오해

HTTP 호출 시 body를 두 번 읽으면 두 번째에 빈 값이 반환된다고 오해하고 있었다.

## 실제 동작

HTTP 호출 시 body를 두 번 읽으면 빈 값이 아닌 TypeError가 발생한다. 

## 왜 그렇게 설계됐는가

100MB 파일을 받는다고 가정해보자.

만약 http response가 스트림이 아니라면 100MB를 전부 메모리에 받게 되고 심각한 메모리 낭비가 발생하게 될 것이다. 

이러한 현상을 방지하기 위해 http body를 스트림으로 설계하게 되었다.

스트림은 소비하면서 조금씩 메모리에 적재하는 방식이기 때문에 메모리 낭비를 방지할 수 있다.

.json()이 Promise인 이유도 비동기적으로 스트림을 소비하기 때문이다.

스트림이 소비되면 bodyUsed 값이 true가 되면서 접근이 막히게 된다.

그래서 body 값을 여러 곳에서 필요로 하는 경우 clone()을 사용해야 한다.

## 확인 방법

API 호출 후 동일한 Response로 여러 번 읽기를 시도했으나 "Body is unusable: Body has already been read" 라는 오류 메시지가 나오며 TypeError가 발생한다.
