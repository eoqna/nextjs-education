# NEXT_PUBLIC 없는 env 가 클라이언트로 새는 경로

**주차:** 3주차
**출처 오답:** 14 일차 항목에서 발생

## 흔한 오해

NEXT_PUBLIC_ 이 없으면 클라이언트에서 안 보인다

## 실제 동작

클라이언트 컴포넌트에서 서버 전용 env를 읽으면 번들에는 안 들어가지만 SSR 결과 HTML에 박혀서 나간다.

## 왜 그렇게 되는가

빌드 타임과 런타임을 나눠서 봐야 한다.

**빌드 타임** — 번들러는 `NEXT_PUBLIC_` 이 붙은 것만 값 문자열로 치환한다.
나머지는 치환하지 않고 조회하는 코드를 그대로 남긴다. 빌드 산출물을 열어보면 이렇다.

```js
let e = t.default.env.DB_PASSWORD,     // 치환 안 됨 → 조회 코드로 남는다
    n = "https://api.example.com";     // 값으로 치환됨
```

그래서 **번들에는 값이 없다.**

**런타임** — 그 조회 코드가 어디서 도느냐에 따라 결과가 갈린다.
서버에서 돌면 `process.env` 가 실제로 있으니 값이 읽히고, 브라우저에서 돌면 없으니
`undefined` 가 된다.

그런데 **클라이언트 컴포넌트도 최초 요청 때는 서버에서 한 번 렌더링된다.**
그때 값이 읽혀서 HTML 에 박히고, 그 HTML 이 브라우저로 간다.

```
JS 번들   super_secret_123  →  0회      "안전하네"
HTML      super_secret_123  →  3개      실제로는 나갔다
```

번들만 확인하고 안심하면 놓친다. 그리고 하이드레이션 후에는 `undefined` 가 되므로
값이 사라지거나 불일치가 날 수도 있다.

문서에 적힌 *"replaces them with an empty string"* 은 **클라이언트 번들에 한한
이야기**였다.

## 어떻게 막는가

서버에서 조회한 값을 클라이언트 컴포넌트를 넘겨주고 클라이언트는 데이터만 전달받아야 한다.

## 확인 방법

.env.local에 두 개의 값을 설정하고 각각 NEXT_PUBLIC_SECRET_KEY, SECRET_KEY로 지정한 다음 클라이언트 컴포넌트에서 해당 값을 조회한 후 확인한다.
